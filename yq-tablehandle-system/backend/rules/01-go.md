# Go 工程规则

## 版本与依赖

- 沿用仓库 Go 版本（`go.mod` 的 `go 1.23.0`）与 module 路径（`codeup.aliyun.com/yuanqisenlin/template-gf`）；不升级语言版本、不引入未经确认的第三方库。
- 新增依赖前说明标准库与已有组件为何不够；同一能力已有库则复用，不装第二套。
- 接口在消费方小范围定义；不为「将来可能」预建接口、泛型或策略层。

## 错误

- 业务失败一律返回 `error`，不 panic；只有进程启动期配置缺失可以失败退出。
- 不吞错：捕获后要么处理，要么带上下文抛出；降级必须打日志并说明原因；不允许 `_ = err`，禁止静默返回空值。
- 包装错误用 `gerror.Wrap/Wrapf` 保留上下文；上下文至少写清哪个对象、哪个业务键、哪个下游。
- 面向用户的文案直接用中文（`manifest/i18n` 目前是空目录，未接入 `g.I18n`）；不要用 `fmt.Errorf` 生成给前端的提示，它只适合内部包装（存量 logic 的 `fmt.Errorf` 属待收敛）。
- 需要前端分支的错误用 `gerror.NewCode` 显式给码；**不用裸 `gerror.New`**。
  - 裸 `gerror.New` 会被 [`utility/middleware.HandlerResponse`](../utility/middleware/response.go) 兜底成 `-1`（系统错误），对外文案「系统错误，请稍后重试！」。
- 只有 `isClientError` 名单里的码会把原始文案透给调用方：六位业务码（100000–999999）、gcode 的 66/300、内置码 401/403/404/422；51/53/54 由 `normalizeCode` 映射成 422，61 映射成 401，65 映射成 404，都不在名单里。其余码只记日志、对外统一「系统错误，请稍后重试！」。
- 业务规则失败用六位业务码：常量登记在 `internal/consts/error_code.go`，取值与模块段见 [02 §7.3](02-api-validation.md)；新模块先登记再用。

## 并发与资源

- 需要并发的业务必须绑定 `ctx` 且可退出；不用裸 `go func()` 跑业务，不在 goroutine 里丢 `ctx`。
- 并发回收错误用 `errgroup.WithContext`；可变 map/slice 不跨协程共享，确需共享用锁或 channel。
- `ctx` 作首参贯穿调用链；不把 `context.Context` 存进结构体。
- 共享状态用锁或原子操作；`init()` 只做注册（如 `logic/logic.go` 的 `service.RegisterXxx`），不承载业务初始化。
- 资源必须释放：`defer` 关文件、解锁、关事务与客户端；`defer` 里不改写返回值。
- 包级变量仅限只读常量、注册表、全局命名生产者（`task.Producer()`、`kafka.Producer()`）。

## 数据形状

- **金额一律 `decimal.Decimal`（`shopspring/decimal`）**，禁止 `float64`，也不再用「分」的 `int64`。
  - 库内类型 `NUMERIC(18,2)`；`app/template/hack/config.example` 已配 `typeMapping`（`decimal` / `numeric` → `decimal.Decimal`），生成物直接是 `decimal.Decimal`。
  - 新增金额字段由 `TestMoneyUsesDecimal` 兜住：扫描 `model`/`entity`/`do` 拒绝 `float64`，并检查 `config.example` 的 `typeMapping` 仍把 decimal/numeric 映射为 `decimal.Decimal`。
- 时间：库内 `TIMESTAMPTZ`，Go 侧 `*gtime.Time`（与 `model/entity` 一致）；纯日期用 `DATE` 对 `*gtime.Time`。字段名 `xxxAt` / `xxxDate`，时区统一 `Asia/Shanghai`。
- 切片、map 使用前判空；`nil` map 写入会 panic；`WhereIn` 传空切片会生成非法 SQL。
- 返回切片用空切片而非 `nil`：JSON 会变成 `null`，前端要多一层兜底。
- `lo.KeyBy` 这类转换前确认键唯一；冲突显式处理，不静默覆盖。

## 命名与风格

- 包名小写、无下划线、无驼峰，不与标准库重名；不新建 `utils`、`common`、`base` 这类无信息包。跨进程能力放 `utility/`，业务放 `app/template/internal/`。
- 命名分词：**包名用 `-`（中线）连接符，文件名用 `_`（下划线）**。包名/模块路径形如 `template-gf`、`data-task`（`go.mod` 的 module 段同理）；Go 文件名形如 `error_code.go`，不写 `errorcode.go`，不用驼峰。
  - Go 的 `package` 声明必须是合法标识符，不能含 `-`，也不用 `_`：连字符只出现在目录/仓库（包路径）上，`package requestid` 这类声明保持小写无分隔。
  - 例外只有生成物与既有历史文件；新增文件按此命名。
- 导出标识符必须写注释，以标识符名开头，说明用途而非实现。
- 结构体字段说明统一用 `dc`，不用 `description`（接口字段细则见 [02-api-validation.md](02-api-validation.md)）。
- import 分三组：标准库、第三方、本项目；项目内再分 `app/template` 与 `utility`。

## 指针还是值

判据一句话：**需要区分「没给」和「给了空值」时用指针，其余用值。**

| 层 | 用什么 | 原因 |
|---|---|---|
| `entity` / `do`（生成物） | 值 / `interface{}` | 列 NOT NULL；`do` 只传变更字段 |
| `filter` 条件结构 | **指针** | `nil` 不参与条件；值类型 `""` 会被当作未传 |
| `model.XxxInput`（service 入参） | 必填值、可空指针 | 新代码按此写 |
| service 出参 / `Res` | 值 | 输出没有三态 |
| `api` Req | 必填值、可选指针 | 与 Input 一致 |
| 函数参数 | 大结构 `*T`，标量值 | 避免大结构拷贝 |

### 必须用指针

- **查询条件**：`nil` 表示不参与查询；`&""` 表示按空串查。
- **部分更新**：`nil` 不改、`&""` 清空；配合 `g.Map` 或 `do.Xxx{}` 只传变更字段。
- **零值本身合法**：`0`、`false`、`""` 是有效值时，值类型会与「未赋值」混淆。

### 必须用值

- 必填参数：`v:"required"` 已拦住零值，用指针只增加 `*in.X` 与判空噪音。
- `entity`、出参、`Res`：内部一定有值。
- 计算中间结果：值语义更直观。

### 三条实测结论

1. **指针绕过不了 `required`**：gvalid 会解引用判空，`&""`、`&0`、`&false` 依然报 required。要允许 0 就别加 `required`，改用 `min:0`；`bool` 开关同理。
2. **值类型查不了空串**：条件结构里 `string ""` 会被 `IsZero` 跳过；`*string` 指向 `""` 才会参与查询。
3. **`gdb` 默认 `OmitEmpty`**：`Data(struct)` 会忽略值类型零值，指针 `&""` 能写入——「把字段清空」必须传指针或直接写 `g.Map`。

### 反模式

- 全字段指针：调用处满屏 `*in.Xxx` 与 nil 判断。
- `[]*string` 直接进 `WhereIn`：nil 元素会拼出异常条件，先过滤再转值。
- 只判 nil 不判空：`p != nil` 不代表有值，完整判空是 `p == nil || *p == ""`。
- 出参用指针：前端拿到 `null` 还要兜底。
